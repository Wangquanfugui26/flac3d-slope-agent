# 三维边坡数值模拟报告（FLAC3D 7.00）

## 一、任务概要

对一均质三维边坡完成数值模拟全过程：建模 → 自重平衡求解 → 强度折减法安全系数计算 → 结果可视化。

**求解引擎**：FLAC3D 7.00（Itasca，`D:\Flac3d\FLAC\exe64\flac3d700_console.exe`）
**驱动方式**：Windows 控制台 API 脚本化驱动（`flac_console_driver2.py`）
**绘图**：Python 3.9 + matplotlib 3.9.4

## 三、求解流程

### 阶段一：自重应力平衡

```
model new → 建模 → 赋本构参数 → model gravity 0 -9.81 0
→ 施加边界条件 → model solve ratio-local 1e-5 → 导出 slope_gravity.csv
```

自重平衡后导出 2670 个单元的中心坐标、位移（x/y/z）、塑性状态、应力分量。

### 阶段二：安全系数计算（强度折减法 / SSR）

```
model restore "slope_gravity.sav"
model large-strain off
model factor-of-safety bracket 0.8 3.0 filename "slope_fos" ratio-local 1e-5
```

FLAC3D 内置的 `model factor-of-safety` 采用**二分法**逐步折减 c 与 tan(φ)，直至边坡失稳，自动输出安全系数及稳定/失稳状态存档。

## 四、计算结果

### 4.1 安全系数

> ## **FOS = 1.685**
>
> （二分区间 0.8 ~ 3.0，最终稳定态 FOS = 1.677，失稳态 FOS = 1.694）

判定：FOS = 1.685 > 1.5，边坡处于**稳定状态**，具备一定安全储备。

### 4.2 位移

| 状态 | 最大总位移 \|u\| | 最大竖向位移 uy | 最大水平位移 ux |
|---|---|---|---|
| 自重平衡态 | 35.1 mm | −35.1 mm | 9.5 mm |
| 失稳态 | **404.6 mm** | −329.4 mm | 390.9 mm |

- **自重态**：位移以竖向沉降为主（最大 35 mm），符合重力加载特征
- **失稳态**：位移量级跃升一个数量级（404 mm），且**水平位移 ux 达 391 mm**，超过竖向位移——表明滑体以**水平向坡外滑动**为主导，是典型的边坡失稳特征

### 4.3 塑性区

| 状态 | 剪切破坏(当前) | 拉伸破坏(当前) | 曾屈服 | 弹性 |
|---|---|---|---|---|
| 自重平衡态 | 430 | 0 | 1362 | 1308 |
| 失稳态 | 819 | 57 | 1794 | 0 |

- 自重态下山体已存在局部塑性区（430 个单元剪切屈服），主要分布于坡面附近
- 失稳态下**塑性区贯通**：剪切破坏带自坡顶内缘（x ≈ 10~15, y ≈ 14~18）沿弧线延伸至坡趾（x ≈ 16~19, y ≈ 7~10），构成完整的**潜在滑裂面**
- 坡顶后缘出现**张拉破坏**（57 个单元），符合牵引式滑坡的力学机制

### 4.4 应力场

- **竖向应力 σzz**：随埋深单调增大，底部最大压应力约 −430 kPa
- **剪应力 σxy**：在坡脚及滑裂面附近显著集中（峰值约 +43 kPa），与塑性贯通带位置高度吻合

## 五、破坏机制分析

综合位移场、塑性区与应力场，该边坡在强度折减至 FOS = 1.685 时表现为**典型的圆弧形旋转滑动破坏**：

1. **滑体范围**：坡面以内、滑裂面以上的楔形体，最大厚度约 10 m
2. **滑裂面形态**：自坡趾 (≈19, 10) 沿弧形向上延伸，于坡顶内缘 (≈10, 18) 剪出，曲率平缓，符合均质边坡圆弧滑动特征
3. **位移分布**：滑体位移自滑裂面向坡面递增，坡面中部（x ≈ 5~10, y ≈ 15~20）位移最大（≈ 400 mm），呈"头部拉伸、中部推移、趾部剪出"的完整运动图景
4. **驱动机制**：坡体自重产生的下滑力超过滑裂面上抗剪强度（折减后）

## 八、关键技术说明

### 8.1 为什么不用 itasca-mcp 执行工具

`itasca-mcp` 的 5 个执行类工具依赖 `itasca-mcp-bridge`，而 bridge **必须在 FLAC3D 进程内部启动**（实测在独立 Python 中调用会报 `RuntimeError: itasca module not available`）。因此本次模拟改走**控制台直驱**路线，通过 Win32 控制台 API 向 `flac3d700_console.exe` 注入命令并回读屏幕输出，等效实现了脚本化控制。

### 8.2 强度折减法的应变模式要求（实测）

FLAC3D 7.00 的 `model factor-of-safety` 要求**小应变模式**：

```
model restore "slope_gravity.sav"
model large-strain off          ← 必须显式关闭
model factor-of-safety bracket 0.8 3.0 filename "slope_fos" ratio-local 1e-5
```

若不显式指定会先后报 `Large strain mode must be specified` 和 `Solve FOS is only allowed in small strain`，最终解法是**显式 `model large-strain off`**。此要求未见于官方在线文档，为实测结论。

### 8.3 FISH 数据导出配方

FLAC3D 的 FISH 文件 IO 语义与常规语言差异很大，经反复试验确定的可用配方：

```fish
local L = list
L = list.append(L, 'hdr1,hdr2,hdr3')      ; 单引号字符串 = 一个元素（整行）
loop foreach local zz zone.list
    local p = zone.pos(zz)
    local g = zone.gp(zz, 1)
    local row = string(p->x) + ',' + string(gp.disp.x(g))
    L = list.append(L, row)               ; 每行一个字符串元素
endloop
file.open("out.csv", "write", "text")     ; 不接收返回值，设置"当前文件"
file.write(L)                             ; 只接受 1 个参数
file.close                                ; 无参数
```

要点：
- `file.write` **只接受 1 个参数**（不是 `file.write(句柄, 数据)`）
- `file.open` 不返回句柄，是全局"当前文件"语义
- `list("a,b,c")` 会**按逗号拆成 3 个元素**；必须用 `list.append` 逐行追加字符串
- `file.write` 把 list 每个元素写成一行，字符串元素会**逐字符拆行**（因此不能用 `list(...)`）
