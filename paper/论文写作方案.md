## 一、选题定位（先说清楚这篇论文的创新点在哪）

### ❌ 不是创新点的内容

- "我用程序驱动了 FLAC3D" —— 系统级技巧，非科学贡献
- "AI 能把边坡算出来" —— 演示性质，无学术价值
- "FOS = 1.685" —— 常规工程结论，每年发几千篇

### ✅ 真正的创新点（三个层次）

| 层次 | 创新点 | 学术价值 |
|---|---|---|
| **实证层** | 提供 AI 自主完成岩土模拟全流程的**完整一手记录**（96 分钟决策链、10 步 API 反推实验） | 稀缺性——目前几乎无此类可追溯的过程数据 |
| **理论层** | 提出**科学计算中 AI 错误的六分类学**（显式语法 / 隐性约束 / **静默失败** / API 语义 / 编码路径 / 认知错误），并按「可见性 × 可自修正性 × 风险」建立矩阵 | 通用性——可用于任何 AI + 科学软件的评估 |
| **实践层** | 提出**能力边界三层次框架**（可托付 / 需人类把关 / 不可托付），并给出不可伪造验证锚点的设计原则 | 指导性——为工程实践提供可操作准则 |

### 🎯 本文最核心的一句话论点

> **AI 在科学计算中的可靠性，不取决于它能避免多少错误，而取决于它能否对「不可见的错误」建立检测机制。**

这句话要贯穿全文。它把文章从"应用报告"提升为"方法论讨论"。

## 二、论文结构（详细版）

### 第 1 章 引言

**1.1 研究背景**
- 岩土数值模拟的流程复杂性：建模 → 参数 → 本构 → 边界 → 求解 → 判据 → 后处理，任一环节出错都会导致结果失效
- 人力成本高，且重复性工作占比大
- 大语言模型在代码生成、工具调用上的进展，引发"能否自动化"的疑问

**1.2 相关工作**
- AI 在科学计算中的现有研究（多为单一环节，如网格生成、参数反演）
- AI Agent 与工具调用（Tool Use）的进展
- **空白点**：缺乏"AI 端到端完成一个完整专业流程"的实证研究

**1.3 本文贡献**
1. 一份 AI 自主完成三维边坡稳定性分析的完整实证（含 96 分钟可追溯决策链）
2. 科学计算中 AI 错误的六分类学与风险矩阵
3. AI 在岩土数值模拟中的能力边界框架与安全实践建议

---

### 第 2 章 实验设计

**2.1 案例选择**
- 三维均质边坡，坡高 10 m / 坡角 45° / 模型 30×20×6 m
- Mohr-Coulomb 本构，2670 单元
- 判据：强度折减法（SSR）安全系数

**2.2 求解平台与交互通道**
- FLAC3D 7.00（Itasca），控制台模式
- **必须说明**：为何未用官方 MCP 通道（`itasca-mcp-bridge` 需在 FLAC3D 进程内启动，实测独立进程报 `RuntimeError: itasca module not available`）
- 交互方式：Win32 控制台 API（AttachConsole / WriteConsoleInputW / ReadConsoleOutputCharacterW）
- ★ **诚实声明**：该通道属"绕路"方案，非本文推荐实践，仅为完成实验的技术手段

**2.3 评价指标**
- 自主完成度：哪些环节无需人工干预
- 纠错能力：错误发现率、修正准确率、迭代次数
- 安全边界行为：是否在不确定时主动升级给人类

### 第 3 章 AI 自主完成流程的实证

**3.1 建模阶段**
- 几何构建（含"条带式"分层建模以形成 45° 坡面）

**3.2 求解阶段**

### 第 4 章 错误分类学与应对机制

**★ 本文的理论贡献章节**

**4.1 六类错误的定义与实例**

| 类别 | 定义 | 实例 |
|---|---|---|
| C1 显式语法错误 | 报错明确、定位准确 | `print "str"` 不接受裸字符串 |
| C2 隐性约束 | 文档未载、需实测发现 | SSR 的应变模式要求（报错自相矛盾） |
| **C3 静默失败** | **不报错但不生效** | `command...endcommand` 块内 FISH 变量插值失效 |
| C4 API 语义偏差 | 与常规编程先验不符 | `file.write` 只接受 1 个参数 |
| C5 编码/路径问题 | 环境相关 | 中文注释乱码、相对路径解析异常 |
| C6 认知错误 | AI 自身理解偏差 | 几何假设不确定（坡趾标高） |

**4.2 静默失败：最危险的类别**

- 论证：C1/C2/C5 会报错，可被检测；**C3 不报错**，错误会污染结果而不自知
- 案例：FISH `command` 块插值静默传递 `[yb]` 字面量
- 应对：**AI 必须主动设计输出一致性校验**，而非依赖报错
- 本文的应对实例：放弃 FISH 循环插值，改由 Python 生成字面值脚本

**4.3 错误风险矩阵**

| 类别 | 可见性 | 可自修正性 | 风险等级 | 应对策略 |
|---|---|---|---|---|
| C1 显式语法 | 高 | 高 | 低 | 按报错直接修正 |
| C2 隐性约束 | 中 | 中 | 中 | 实测闭环 + 交叉验证 |
| **C3 静默失败** | **无** | **需主动设计检测** | **极高** | **强制输出校验** |
| C4 API 语义 | 低 | 需实验 | 中 | 单变量受控探针实验 |
| C5 编码/路径 | 中 | 中 | 低 | 环境隔离与规范化 |
| C6 认知错误 | 需自省 | 需人工介入 | 高 | 主动升级机制 |

### 第 5 章 结果与验证

**5.1 模拟结果**
- FOS = 1.685
- 最大位移：失稳态 404.6 mm / 自重态 35.1 mm
- 破坏模式：圆弧形旋转滑动（滑裂面自坡趾延伸至坡顶内缘）

**★ 5.2 不可伪造验证锚点的设计**
- 核心论点：科学计算中的 AI 应用**必须提供可被独立核验的证据**
- 本文的三个锚点：
  1. **FLAC3D 原生二进制存档**（`.sav`，4 个共 26 MB）——AI 无法伪造，用户可用 GUI 打开复核
  2. **FLAC3D 自写日志**（`s2.log` 署有 `flac3d Version 7.00 Release 126`）
  3. **物理一致性检验**（应力随深度单调增大、塑性区与应力集中区空间吻合）

---

### 第 6 章 能力边界与安全实践

**6.1 三层次框架**

| 层次 | 环节 | 说明 |
|---|---|---|
| ✅ **可托付** | 几何建模、网格生成、参数赋值、边界条件、求解编排、数据提取、可视化、错误诊断 | 流程性工作，规则明确 |
| ⚠️ **需人类把关** | 物理假设合理性、本构模型选择、参数取值依据、结果工程解读、边界条件与实际的匹配度 | 需专业判断与责任承担 |
| ❌ **不可托付** | 无实测数据支撑的参数确定、涉及重大工程安全的最终判据 | 责任主体必须是人 |

**6.2 人机协作流程建议**
- 让 AI 做"流程执行者 + 纠错助手"
- 人类保留"假设制定者 + 结果裁决者"角色
- **强制要求**：AI 在物理假设不确定时必须主动暂停并升级

**6.3 本文的正面案例**
- AI 在几何理解不确定时，主动提请用户确认坡趾标高，未擅自继续
- 这应成为 AI 参与工程计算的**标准行为规范**

---

### 第 7 章 结论与展望

**结论**
1. AI 可自主完成岩土数值模拟的完整流程，但在"非文档化 API"和"静默失败"面前需强化检测机制
2. 提出六分类错误学，指出静默失败是最需警惕的风险
3. 明确能力边界：AI 是流程执行者，不是工程判断责任主体

**展望**
- 官方 MCP 通道（进程内直连）可显著提升可靠性与效率
- 需要建立"AI 科学计算"的验证标准与审计规范
- 多案例、多软件平台的横向对比研究
