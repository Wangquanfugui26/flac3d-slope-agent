## 一、核心命题

**"大语言模型驱动的 AI Agent 能否独立完成一次符合工程规范的岩土数值模拟全过程？"**

本次工作是一份完整的实证样本，而非演示。关键特征：

1. **零人工干预建模**：AI 独立完成几何构建、网格划分、本构赋值、边界条件、荷载施加
2. **自主求解与判据选择**：独立选用强度折减法（SSR）求安全系数
3. **自主纠错**：途中自主发现并修正 6 类错误
4. **主动质疑自身假设**：对几何理解不确定时主动提请人工确认（安全边界行为）

### 3.2 FISH file IO 攻坚阶段（16:59 – 17:17）★ 最核心的决策链

> 10 个探针，逐步逼近正确语义。是本论文"AI 自主纠错能力"的最强证据。

| 时刻 | 探针 | 假设 | 结果 |
|---|---|---|---|
| 16:59 | `_probe_io.dat` | `file.write(fid, list(...))` | 失败（0 字节） |
| 17:01 | `_probe_io2.dat` | `file.write(fid, lst)` 分离变量 | 写入成功但**逐字符成行** |
| 17:02 | `_probe_io3.dat` | `file.write(fid, list(a,b,c))` 多元素 | **报错：Too many arguments to intrinsic (1 accepted)** |
| 17:09 | `_probe_io4.dat` | 复现确认参数个数错误 | 确认 `file.write` 只接受 **1 个参数** |
| 17:10 | `_probe_io5.dat` | `file.open(...)` 不接收返回值 + `file.write(L)` | ✅ 成功！但发现字符串被逐字符拆分 |
| 17:14 | `_probe_io6.dat` | 嵌套列表 `list.append(L, list(...))` | 报错（list.append 参数问题） |
| 17:15 | `_probe_io7.dat` | 索引赋值 `L(2) = 'string'` | 部分成功，揭示 `list('a,b,c')` 按逗号拆分 |
| 17:16 | `_probe_io8.dat` | 动态索引 `L(cnt) = row` | 报错：`Index 1 out of range` |
| 17:16 | `_probe_io9.dat` | `list.append(L, row)` 增长列表 | ✅ 成功（n=15）但表头仍被拆分 |
| 17:17 | `_probe_io10.dat` | **空列表 + append 整行字符串** | ✅✅ **完全正确！干净 CSV** |

**最终正确配方**：
```fish
local L = list
L = list.append(L, 'hdr1,hdr2,hdr3')      ; 单引号字符串 = 一个元素（整行）
loop foreach local zz zone.list
    ...
    L = list.append(L, row_string)        ; 每行一个字符串元素
endloop
file.open("path.csv", "write", "text")    ; 不接收返回值，设置"当前文件"
file.write(L)                             ; 只接受 1 个参数
file.close                                ; 无参数
```

## 四、六类错误分类（论文第 4 节核心素材）

> 这是本文的**理论贡献**：AI 在专业软件中遇到的错误可分为不同类别，各类需要不同的应对策略。

### 类别 1：显式语法错误（易修正）

| 错误 | 表现 | 修正 |
|---|---|---|
| E1 | `print "STRING"` → 语法错误 | 改用 `program echo` / `io.out` |
| E2 | `call file.dat` → Bad conversion | 加引号 `call "file.dat"` |
| E3 | `group lower` → Bad conversion | 加引号 `group "lower"` |
| E4 | `loop local i = 0 3` → 语法错误 | 改 `loop local i (0, 3) ... endloop` |

**特征**：报错信息明确、定位准确，AI 一次修正即可。

### 类别 2：跨版本/文档缺失的隐性约束（难，需实测）

| 错误 | 表现 | 修正 |
|---|---|---|
| E5 | FOS 报 `Large strain mode must be specified` | 加 `model large-strain on` |
| E6 | FOS 报 `Solve FOS is only allowed in small strain` | 改为 `model large-strain off` |

**★ 关键发现**：E5 与 E6 **互相矛盾**，官方在线文档均未提及。
最终解：**必须显式 `model large-strain off`**。

**论文价值**：这揭示了"AI 无法仅依赖文档推理"的根本限制，必须依赖**实测反馈闭环**。

### 类别 3：静默失败（最危险）★★★

| 错误 | 表现 | 危险度 |
|---|---|---|
| E7 | `command...endcommand` 块内 `[fisg_var]` 插值**不报错但也不生效**，原样传递 | 极高 |

**论文价值**：这是 AI Agent 在科学计算软件中面临的**最严重风险**——错误不会暴露，结果静默错误。
**应对策略**：AI 必须主动设计**输出一致性校验**（本次通过"生成字面值脚本"绕开）。

### 类别 4：API 语义与直觉不符（需实验反推）

| 错误 | 假设 | 实测真相 |
|---|---|---|
| E8 | `file.write(handle, data)` | **只接受 1 个参数**，是全局"当前文件"语义 |
| E9 | `file.open() ` 返回句柄 | 不返回，仅设置当前文件 |
| E10 | `list("a,b,c")` = 一个字符串 | **按逗号拆成 3 个元素** |
| E11 | 写入字符串 = 写入一行 | **逐字符拆成多行** |

**论文价值**：这类问题**无法从文档推断**，只能通过**受控实验（探针序列）**反推。
本论文记录了完整的 10 步反推过程，可作为方法论范例。

### 类别 5：数据/编码类错误

| 错误 | 表现 | 修正 |
|---|---|---|
| E12 | 中文注释在 .dat 中乱码（`涓嬮儴宀╃綋`） | 生成脚本用 `encoding="ascii"` |
| E13 | `call "相对路径"` 解析到默认工程目录 | 必须用绝对路径 |

### 类别 6：自身认知错误（AI 主动暴露）

| 错误 | 表现 | 应对 |
|---|---|---|
| E14 | 几何理解不确定（坡趾 y=10 还是 y=0） | **AI 主动提请人工确认**，未擅自继续 |

**论文价值**：这是**安全边界行为**的正面案例——AI 识别到自身假设的不确定性，主动升级给人类决策。

## 五、错误分类学（论文的通用性贡献）

| 类别 | 可见性 | 可自修正性 | 风险等级 | 应对策略 |
|---|---|---|---|---|
| 1 显式语法 | 高 | 高 | 低 | 直接按报错修正 |
| 2 隐性约束 | 中 | 中 | 中 | 实测闭环 + 交叉验证 |
| 3 **静默失败** | **无** | **需主动设计检测** | **极高** | **强制输出校验** |
| 4 API 语义 | 低 | 需实验 | 中 | 受控探针实验 |
| 5 编码/路径 | 中 | 中 | 低 | 环境隔离与规范化 |
| 6 认知错误 | 需自省 | 需人工介入 | 高 | **主动升级机制** |

**核心论点**：AI 在科学计算中的可靠性，不取决于它能避免多少错误，而取决于它**能否对"不可见的错误"建立检测机制**。

## 七、讨论：AI 在岩土数值模拟中的能力边界

### 可以可靠替代的环节
- 几何建模与网格生成（规则几何）
- 材料参数赋值、边界条件设置
- 常规求解流程编排
- 数据提取与可视化
- 错误诊断与修正迭代

### 必须人类把关的环节
- **物理假设的合理性**（本例：坡趾位置）
- **本构模型选择**（为何用 Mohr-Coulomb？是否需考虑软化？）
- **参数取值依据**（c=30kPa 从何而来？有无勘察依据？）
- **结果工程解读**（FOS=1.685 是否满足规范？）
- **边界条件与实际情况的匹配度**

### 不可托付的环节
- 无实测数据支撑的参数确定
- 涉及重大工程安全的最终判据

**结论**：AI 可作为**高效的流程执行者与纠错助手**，但不能取代**工程判断责任主体**。
