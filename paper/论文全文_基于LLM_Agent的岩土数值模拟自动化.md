# 基于大语言模型 Agent 的岩土数值模拟自动化实践与能力边界分析

---

## 摘要

**目的**：验证大语言模型（LLM）驱动的 AI Agent 能否独立完成一次符合工程规范的岩土数值模拟全过程，并厘清其能力边界与失效模式。**方法**：以三维均质边坡稳定性分析为案例，由 AI Agent 在无人工干预条件下独立完成几何建模、网格划分、本构赋值、边界条件设置、自重平衡求解、基于强度折减法（SSR）的安全系数计算及结果可视化。全过程记录可追溯的决策链与失败-修正路径，并对所遇错误进行分类学分析。**结果**：AI Agent 在 96 分钟内完成全流程，最大瞬时计算规模 2670 单元，求得安全系数 FOS = 1.685，破坏模式为圆弧形旋转滑动；过程中自主识别并修正 6 类共 14 项错误。**结论**：AI Agent 可胜任岩土数值模拟的流程性工作，但面对"非文档化 API 语义"与"静默失败"两类错误时存在系统性脆弱性。本文提出科学计算中 AI 错误的六分类学与风险矩阵，并确立"可托付—需人类把关—不可托付"的三层次能力边界框架。研究表明：**AI 在科学计算中的可靠性，不取决于它能避免多少错误，而取决于它能否对"不可见的错误"建立检测机制。**

**关键词**：大语言模型；AI Agent；岩土数值模拟；FLAC3D；强度折减法；错误分类学；人机协作

## 1 引言

### 1.1 研究背景

岩土数值模拟是岩土工程分析的核心手段，其流程冗长且环环相扣：从几何建模、网格划分、材料参数确定、本构模型选择、边界条件施加，到求解策略设置、失稳判据选取，直至结果提取与工程解读。任一环节的疏漏都可能导致计算结果失效，而这种失效往往不会以"报错"的形式出现——它可能表现为一个看似合理却物理错误的数值。

这一特征使得岩土数值模拟成为高度依赖专业经验的劳动密集型工作。其中，几何构建、参数批量赋值、结果后处理等环节具有强烈的规则性，理论上具备自动化的可能。

近年来，大语言模型在代码生成、工具调用（Tool Use）与多步推理方面取得显著进展，引发了"AI 能否自动化专业工程计算"的广泛讨论。然而，现有讨论多停留于演示层面，缺乏可追溯的过程实证研究。

### 1.2 相关工作与空白点

AI 在科学计算中的应用研究目前多集中于**单一环节**，例如：

- 基于机器学习的网格质量优化
- 基于神经网络的岩土参数反演
- 基于符号回归的本构模型发现

而在**端到端流程自动化**方面，尤其是"AI 独立完成一个完整专业流程"的实证研究仍属空白。关键原因在于：

1. 缺乏完整的、可追溯的过程记录（成功案例往往只报告结果，不报告路径）
2. 商业软件的封闭性导致交互通道受限
3. 难以界定"AI 完成"与"人辅助 AI 完成"的边界

### 1.3 本文贡献

本文以一次真实的、完整的边坡稳定性分析为例，提供以下三方面贡献：

**(1) 实证层面**：提供 AI 自主完成岩土数值模拟全流程的一手过程记录，包括 96 分钟可追溯决策链，以及一次历时 18 分钟的"非文档化 API 语义"十步反推实验。

**(2) 理论层面**：提出科学计算中 AI 错误的**六分类学**（显式语法错误、隐性约束、静默失败、API 语义偏差、编码路径问题、认知错误），并按"可见性 × 可自修正性 × 风险等级"建立评估矩阵，指出**静默失败**是其中最危险且最易被忽视的类别。

**(3) 实践层面**：确立 AI 在岩土数值模拟中的**三层次能力边界框架**（可托付 / 需人类把关 / 不可托付），并提出"不可伪造验证锚点"的设计原则，为工程实践中引入 AI 提供可操作的准则。

## 2 实验设计

### 2.1 案例选择

选取三维均质边坡稳定性分析作为实验案例，理由如下：

- 该问题**流程完整**：涵盖建模、求解、失稳判据、后处理的全部环节
- 该问题**判据明确**：强度折减法给出的安全系数是客观、可复核的定量指标
- 该问题**物理可验证**：破坏模式可通过位移场、塑性区、应力场的一致性交叉检验

**模型几何**（表 1）：总长 30 m（x 向）、总高 20 m（y 向）、厚度 6 m（z 向）；坡高 10 m，坡角 45°，坡趾至右边界水平距离 10 m。

**表 1 模型几何参数**

|---|---|
| 模型总长（x） | 30 m |
| 模型总高（y） | 20 m |
| 模型厚度（z） | 6 m |
| 坡高 | 10 m |

| 坡趾坐标 | (x = 20, y = 10) |

**网格划分**：采用"分层条带"策略构建 45° 坡面——下部块体（y = 0 ~ 10 m，全宽 30 m）划分为 30 × 10 × 6 = 1800 个单元；上部坡体由 10 层条带组成，每层高 1 m，x 向边界自 19 m 递减至 10 m（对应 45° 坡面），共 870 个单元。**总单元数 2670。**

### 2.2 求解平台与交互通道

**求解平台**：FLAC3D 7.00（Itasca Consulting Group），显式有限差分法，控制台模式（`flac3d700_console.exe`）。

**交互通道的选择与说明**：

本实验原计划采用 Itasca 官方的 MCP（Model Context Protocol）通道（`itasca-mcp` + `itasca-mcp-bridge`）。然而实测发现，`itasca-mcp-bridge` 的执行类工具**必须在 FLAC3D 进程内部启动**，在独立 Python 进程中调用会抛出：

```
RuntimeError: itasca module not available; run bridge inside an ITASCA product GUI
```

由于 AI Agent 无法在已运行的 GUI 进程内部注入 Python 代码，官方 MCP 通道在本实验条件下不可用。

因此，本实验采用**控制台 API 直驱**作为替代交互通道，其技术路径为：

1. `CreateProcess` 启动 `flac3d700_console.exe`（`CREATE_NEW_CONSOLE`）
2. `FreeConsole()` 解除自身控制台绑定
3. `AttachConsole(pid)` 附加至目标进程控制台
4. `WriteConsoleInputW` 以键盘事件形式注入 FLAC3D 命令
5. `ReadConsoleOutputCharacterW` 回读屏幕缓冲区，判定执行状态

> **诚实声明**：该通道属"绕路"方案，而非本文推荐的最佳实践。其固有缺陷包括：命令发送与结果读取之间存在轮询延迟（本实验采用 4 秒间隔），显著降低端到端效率（详见 §5.3）。该通道仅作为在官方通道不可用时完成本实验的技术手段，**不应被视为本文的方法学贡献**。

### 2.3 评价指标

本文从三个维度评价 AI Agent 的表现：

(1) **自主完成度**：哪些环节在无人工干预条件下完成，哪些环节需要人工介入。

(2) **纠错能力**：错误的发现率（是否被察觉）、修正准确率（是否一次修正成功）、迭代次数。

(3) **安全边界行为**：是否在自身认知不确定时主动暂停并升级给人类决策，抑或擅自继续。

## 3 AI Agent 自主完成流程的实证

### 3.1 建模阶段

AI Agent 首先需确定 FLAC3D 的建模命令语法。初始尝试即暴露第一类错误：

**错误 1（C1 显式语法）**：使用 `print "PROBE1_OK"` 输出标记，报语法错误。原因是 FLAC3D 的 `print` 命令不接受裸字符串参数。修正方案：改用 `program echo` 或 FISH 的 `io.out`。

**错误 2（C1 显式语法）**：`list zone` 报错，因其缺少限定词（qualifier）。需改为 `zone list`。

确定语法后，AI Agent 面临**几何构建的设计决策**：FLAC3D 的 `zone create brick` 只能生成六面体块，无法直接生成 45° 斜面。AI Agent 自主设计了"分层条带"方案：将上部坡体离散为 10 层各 1 m 高的条带，第 i 层（y 自 10+i−1 至 10+i）的 x 向边界取 `x_right = max(10, min(20, 30 − y_top))`，从而形成从坡趾 (19, 10) 到坡顶内缘 (10, 19) 的 45° 阶梯状斜面（图 1）。

**图 1** 建模命令序列（节选，完整脚本见附录 B）
```
zone create brick point 0 (0,0,0) point 1 (30,0,0) point 2 (0,10,0) point 3 (0,0,6) size 30 10 6 group "lower"
zone create brick point 0 (0,10,0) point 1 (19,10,0) point 2 (0,11,0) point 3 (0,10,6) size 19 1 6 group "upper"
...
zone create brick point 0 (0,19,0) point 1 (10,19,0) point 2 (0,20,0) point 3 (0,19,6) size 10 1 6 group "upper"
```

**错误 3（C1 显式语法）**：早期的 FISH 循环方案中，`loop local i = 0 3` 报语法错误。修正：FLAC3D 的 FISH 循环语法为 `loop local i (0, 3) ... endloop`。

**错误 4（C3 静默失败）★**：AI Agent 最初尝试用 FISH 循环 + 变量插值动态生成几何，即在 `command ... endcommand` 块内使用 `[yb]` 形式的变量插值。实测发现：**该插值不报错，但也不生效**——变量名被原样作为字面量传递。这导致模型几何静默错误。

这是本文所遇**最严重**的错误类型。修正方案：AI Agent 放弃 FISH 循环方案，改由外部 Python 脚本**生成全部坐标为字面数值的 .dat 文件**。该修正虽然牺牲了脚本的简洁性，但消除了静默失败的可能。

**错误 5（C5 编码/路径）**：生成脚本时使用中文注释，导致 .dat 文件在 FLAC3D 中显示乱码（`涓嬮儴宀╃綋`）。修正：生成脚本时采用 `encoding="ascii"`，移除所有非 ASCII 字符。

**错误 6（C5 编码/路径）**：`call "_p6.dat"` 报 `Bad conversion` 错误，提示 `NOTE: String tokens must be surrounded by " or ' characters.`。修正：文件名必须加引号。

**错误 7（C5 编码/路径）**：`group lower` 报同样错误。修正：`group "lower"`。

**错误 8（C5 编码/路径）★**：`call "相对路径.dat"` 被 FLAC3D 解析至其默认工程目录 `C:\Users\...\Documents\Itasca\flac3d700\My Projects\`，导致文件打开失败。修正：所有文件路径必须使用绝对路径。

### 3.2 求解阶段

#### 3.2.1 自重应力平衡

边界条件施加后执行 `model solve ratio-local 1e-5`。求解**在 9 秒内收敛**：共 4751 个计算步，最终局部不平衡力比为 9.6343 × 10⁻⁶，满足收敛标准。

求解完成后，AI Agent 通过 FISH 脚本导出全部 2670 个单元的结果数据（单元中心坐标、位移三分量、塑性状态、应力分量）至 CSV 文件，供 Python 后处理。此导出功能的实现过程详见 §3.4。

#### 3.2.2 强度折减法计算安全系数

AI Agent 自主选择强度折减法（Strength Reduction Method, SSR）作为安全系数判据，调用 FLAC3D 内置的 `model factor-of-safety` 命令。

**错误 9（C2 隐性约束）★★**：首次执行即报错：

```
*** Solve FOS is only allowed in small strain.
```

AI Agent 据此推测需关闭大应变模式，但此前在早期探针实验（15:52 的 `_p4.dat`）中，曾遇到**相反的报错**：

```
*** Large strain mode must be specified with the MODEL LARGE-STRAIN command.
```

**两项报错互相矛盾**，且 Itasca 官方在线文档对 `model factor-of-safety` 的应变模式要求**只字未提**。AI Agent 通过进一步实测确定最终解：**必须在 `model restore` 之后显式执行 `model large-strain off`**，方可执行 FOS 计算。

**该发现的价值在于**：它证明 AI Agent 无法仅凭文档推理正确配置复杂的专业软件——必须依赖**实测反馈闭环**。这一结论对"AI 能否可靠使用专业软件"的讨论具有普遍意义。

修正后，`model factor-of-safety` 正常执行。计算采用二分法（bisection），在区间 [0.8, 3.0] 内迭代 16 轮，特征步数 4566，**耗时约 4 分钟**，输出：

```
--- Factor of Safety is : 1.69
Last Factor of Safety Calculated: 1.685
```

迭代过程的收敛轨迹见表 4。

**表 4 强度折减法二分迭代收敛轨迹**

| 阶段 | 稳定态 FOS | 当前 FOS | 失稳态 FOS | 累计耗时 |
|---|---|---|---|---|

### 3.3 后处理阶段

AI Agent 独立编写 Python 脚本（matplotlib）完成可视化，输出 11 张成果图，包括：安全系数汇总、位移云图（总量/竖向/水平）、塑性区分布、位移矢量场、应力场（σzz / σxy）。

**错误 10（C4 API 语义）**：尝试用 Python 生成绘图脚本时，managed Python 3.13 环境**未安装 matplotlib**（`ModuleNotFoundError`）。AI Agent 自主检索系统内其他 Python 环境，发现系统 Python 3.9（`D:\VS\Shared\Python39_64\python.exe`）已含 matplotlib 3.9.4，遂切换环境完成绘图。

**错误 11（C4 API 语义）**：首次绘图时，塑性区分布图**无信息量**——因失稳态下全部 2670 个单元均为"曾剪切屈服"（shear-p），导致图面被单一颜色覆盖。AI Agent 自主改进可视化逻辑：区分"当前破坏"（shear-n / tension-n）与"历史屈服"（仅 shear-p），使活跃滑裂带得以显现。

### 3.4 ★ FISH 文件 I/O 的十步反推实验

本节记录 AI Agent 为实现结果数据导出而进行的 10 次受控实验。该过程是"AI 通过实验反推非文档化 API 语义"的典型案例，总耗时 18 分钟（16:59 – 17:17）。

**初始假设**（源自常规编程经验）：`file.write(文件句柄, 数据)`，与 C/Python 的 `f.write()` 语义一致。

实验过程与认知演进见表 5。

**表 5 FISH 文件 I/O 语义的十步反推实验**

| 序号 | 时刻 | 假设 | 观测结果 | 认知修正 |
|---|---|---|---|---|
| 1 | 16:59 | `file.write(fid, list(...))` | 输出 0 字节，无报错 | 静默失败，需重新假设 |
| 2 | 17:01 | 分离变量声明 | 写入 207 字节，但**逐字符成行** | `file.write` 逐元素输出；字符串被视作字符列表 |
| 3 | 17:02 | `list("a","b","c")` 多元素 | **报错**：`Too many arguments to intrinsic (1 accepted)` | ★ `file.write` 只接受 1 个参数 |
| 4 | 17:09 | 复现确认 | 同样报错 | 确证：FISH 采用**全局"当前文件"**模型，非句柄传递 |
| 5 | 17:10 | `file.open(...)` 不接收返回值 + `file.write(L)` | ✅ 成功 | ★ 核心语义确认 |
| 6 | 17:14 | 嵌套列表 | 报错：`Too many arguments` | `list.append` 调用形式特异 |
| 7 | 17:15 | 索引赋值 `L(2)='str'` | ✅ 部分成功，整串输出为一行 | ★ `list(长字符串)` 会**逐字符拆分** |
| 8 | 17:16 | 动态索引 `L(cnt)=row` | 报错：`Index 1 out of range (1,0)` | 裸 `list` 构造空表，不能索引扩张 |
| 9 | 17:16 | `list.append(L, row)` | ✅ 成功（n=15），但表头仍拆行 | `list.append` 可用，返回新列表 |
| 10 | 17:17 | **空列表 + append 整行字符串** | ✅✅ **完全正确的 CSV** | 收敛到正确配方 |

**最终确定的 FISH 文件 I/O 正确语义**（表 6）：

**表 6 FISH 文件 I/O 正确用法**

| 操作 | 正确语法 | 关键约束 |
|---|---|---|
| 打开文件 | `file.open(路径, "write", "text")` | **不接收返回值**；模式与类型必须是字符串 |
| 写入数据 | `file.write(列表)` | **只接受 1 个参数**；列表每个元素输出为一行 |
| 构造列表 | `local L = list` 后 `L = list.append(L, 字符串)` | **禁止 `list(长字符串)`**（会逐字符拆分） |
| 关闭文件 | `file.close` | 无参数 |

**方法论启示**（三点）：

1. 面对非文档化 API，AI 的常规编程先验（"句柄式 I/O"）会**系统性误导**，且该误导可能不产生任何报错。
2. 有效策略是**单变量受控实验**——每轮只修改一个假设点，通过排除法逐步收敛。
3. **异常输出（逐字符成行）比报错携带更多信息**——它揭示了底层数据模型（字符串 = 字符列表），这是纯粹从报错中无法获得的。

## 4 科学计算中 AI 错误的六分类学

### 4.1 分类框架

基于 §3 中记录的 14 项错误，本文提出科学计算中 AI 错误的六分类学（表 7）。

**表 7 AI 错误六分类学**

| 类别 | 定义 | 本文实例 | 报错可见性 |
|---|---|---|---|
| **C1 显式语法错误** | 违反语言/命令的语法规则，报错明确且定位准确 | `print "str"`；`loop i = 0 3` | 高 |
| **C2 隐性约束** | 软件要求存在但文档未载，或文档描述矛盾 | SSR 的应变模式要求 | 中 |
| **C3 静默失败** | 代码不报错，但语义未生效，结果被污染 | `command` 块内 FISH 变量插值失效 | **无** |
| **C4 API 语义偏差** | API 的实际语义与常规编程先验或文档描述不符 | `file.write` 只接受 1 个参数 | 低 |
| **C5 编码/路径问题** | 由字符集、路径解析规则等环境因素引发 | 中文注释乱码；相对路径解析异常 | 中 |
| **C6 认知错误** | AI 自身对问题理解的偏差 | 几何假设不确定（坡趾标高） | 需自省 |

### 4.2 静默失败：最危险的类别

在所有类别中，**C3 静默失败**具有特殊的危险性，理由如下：

**其一，它绕过了 AI 的纠错机制。** AI 纠错的核心依赖是"报错-修正"闭环（如 §3 中 C1、C2、C5 类错误的修正均依赖报错信息）。而静默失败**不产生任何错误信号**，AI 会在"一切正常"的假象下继续推进，直至结果完全错误。

**其二，它污染的是中间结果而非最终输出。** 本文中，FISH 变量插值的静默失败导致**模型几何错误**——若未被察觉，后续的求解、FOS 计算、可视化将全部建立于错误的几何之上，而每一步都"正常完成"。这类错误具有**传播性与隐蔽性**。

**其三，它的检测需要主动设计。** 应对静默失败，唯一可行的策略是**主动构造输出一致性校验**，而非被动等待报错。

**本文的应对实例**：AI Agent 在遭遇 FISH 插值静默失败后，放弃"动态参数化脚本"方案，转而由外部 Python 脚本生成**全部为字面数值**的 .dat 文件。这一策略的本质是：**以"放弃灵活性"换取"消除静默失败的可能性"**——因为字面值不存在"插值是否生效"的不确定性。

这一权衡具有普遍参考价值：**在对可靠性要求高于灵活性的科学计算场景中，应优先选择语义确定、无隐式行为的实现路径。**

### 4.3 错误风险矩阵

综合"可见性"与"可自修正性"两个维度，建立风险矩阵（表 8）。

**表 8 AI 错误风险矩阵**

| 类别 | 可见性 | 可自修正性 | 风险等级 | 应对策略 |
|---|---|---|---|---|
| C1 显式语法错误 | 高 | 高 | 低 | 按报错信息直接修正 |
| C2 隐性约束 | 中 | 中 | 中 | 实测反馈闭环 + 交叉验证 |
| **C3 静默失败** | **无** | **需主动设计检测** | **极高** | **强制输出一致性校验** |
| C4 API 语义偏差 | 低 | 需实验 | 中 | 单变量受控探针实验 |
| C5 编码/路径问题 | 中 | 中 | 低 | 环境隔离与路径规范化 |

**矩阵的实践含义**：AI 在科学计算中的可靠性提升路径，**不应均匀分配于所有错误类别**，而应重点投入于 C3（建立检测机制）与 C6（建立升级机制）。这两个类别是当前 AI 能力的主要短板，也是人机协作分工的关键界面。

## 5 结果与验证

### 5.1 验证策略：以独立方法交叉校核

**核心论点**：AI Agent 生成的数值结果，**必须由与生成过程完全独立的第二条路径来校核**，否则"正确结果"与"看似合理的编造"无法区分。

本文不采用"存档文件 AI 无法伪造"这类自指式论证——因为该论证无法排除"AI 调用软件得到了错误结果"的情形。本文建立三层递进验证：

| 层次 | 校核手段 | 排除的错误 |
|---|---|---|
| L1 复现性 | 同一算例重复运行，结果逐位一致 | 随机性、并发污染 |
| L2 独立方法交叉 | 极限平衡法（Bishop 简化法）独立求解 FOS | 数值实现错误、本构误用 |
| L3 极端工况覆盖 | 低强度、陡坡算例均能解出且与 Bishop 一致 | 判据误设、几何缺陷 |

**L2 的独立性论证**：Bishop 简化法为**条分法**，将滑体离散为竖向土条，逐条建立力矩平衡，其力学假设（圆弧滑面、条间力竖向平衡、忽略条间剪力）与 FLAC3D 的**连续介质有限差分 + 强度折减**在数学结构上完全独立——二者不共享任何代码、离散方式或求解路径。因此二者的吻合具有真实的校核意义。

### 5.2 基准算例及其验证

基准算例：坡高 H = 10 m，坡角 θ = 45°，黏聚力 c = 30 kPa，内摩擦角 φ = 25°，容重 25 kN/m³，模型 30 m × 20 m × 6 m（平面应变）。

**L1 复现性**：该算例在完全独立的两次运行中给出**逐位一致**的结果：

| 运行 | 特征步数 | FOS |
|---|---|---|
| 运行 1（早期手工交互） | 4566 | 1.685 |
| 运行 2（修复后批处理管道） | 4342 | 1.685 |

两次运行的时间相隔数小时、驱动方式不同（手工交互 vs 批处理脚本），但 FOS 完全一致（1.685）。特征步数的差异（4566 vs 4342）源于 `model random` 种子生效顺序的细微不同，属正常数值波动，不影响折减结果。

**L2 独立方法交叉**：

| 方法 | 原理 | FOS |
|---|---|---|
| FLAC3D SSR | 连续介质有限差分 + 强度折减 | **1.685** |
| Bishop 简化法 | 极限平衡条分法 | **1.578** |
| 相对偏差 | — | **+6.8 %** |

该偏差方向与量级**符合已建立的文献共识**：强度折减法（考虑真实应力路径与变形协调）通常给出略高于极限平衡法的 FOS，典型差异在 5 %–15 % 区间。本文的 +6.8 % 落在该区间内，表明两者相互印证。

### 5.3 极端工况验证：低强度与陡坡

为检验管道在"非平凡"工况下的稳健性，补充两个极端算例：

**表 11 三算例交叉验证汇总**

| 算例 | 参数 | FLAC3D FOS | Bishop FOS | 相对偏差 |
|---|---|---|---|---|
| base45 | c=30, φ=25, θ=45° | 1.685 | 1.5778 | **+6.80 %** |
| c10p15 | c=10, φ=15, θ=45° | 0.750 | 0.6990 | **+7.30 %** |
| t60 | c=30, φ=25, θ=60° | 1.320 | 1.2494 | **+5.65 %** |

偏差范围 **+5.65 % ~ +7.30 %**，均值 **+6.58 %**。

**该结果的意义有三**：

1. **符号一致**——三个算例的 FLAC3D 值**全部高于** Bishop 值，无符号翻转；
2. **量级稳定**——偏差极差仅 1.65 个百分点，不随强度或坡角系统性漂移；
3. **落在文献区间**——强度折减法较极限平衡法高 5 %–15 % 属已建立共识，本文结果居于该区间下沿。

三者共同表明：FLAC3D SSR 与 Bishop 简化法之间的偏差是一个**稳定的方法学差异**，而非随机误差或实现缺陷。

**c10p15 的意义**：该算例首次 SSR 求解返回：

```
+++ Model is unstable at maximum specified Factor of Safety 0.8.
Factor of Safety Not Valid
```

将搜索下界由 0.8 放宽至 0.3 后，成功解出 **FOS = 0.75**，与 Bishop 的 0.699 偏差仅 +7.3 %。**两个独立方法在低强度区间仍保持一致**，说明管道在远离基准点的参数空间同样可靠。

### 5.3.1 ★ 陡坡算例的静默失效：网格共形性

`t60`（θ=60°）的排查过程揭示了一个**此前未被记录的静默失效模式**，其危险程度高于本文所述任何其他错误。

**现象**：`t60` 的自平衡阶段 `ratio-local` **恒等于 1.00000e+00**——推进 200 000 步、耗时 242 s，该比值**一位小数都不变**，且 `***` 错误计数为 **0**，`.sav` 亦能正常写出（但为无效状态）。由其出发的 SSR 求解，无论将 bracket 下限压至 0.8、0.3 乃至 0.05，**一律返回 `Not Valid`**。

**根因**：FLAC3D 的 `zone create brick` **不会自动缝合非共形界面**。本模型下部整块为 `size 30 10 6`，x 向单元尺寸恰为 1.000 m。上部阶梯条带若其右边界不落在整数上（θ=60° 时为 18.8453 m 等），则条带单元尺寸（0.9919 m）与下部块（1.0000 m）**错位**，两块网格**互不连通**——上部坡体成为自由悬浮体，重力无法向下传递，故不平衡力比恒为 1。

**实测对照**：

| 条带右边界 xr | 段数 nx | 单元尺寸 | 网格 | 自平衡 |
|---|---|---|---|---|
| 19.0000 | 19 | 1.0000 m | 共形 | ✔ 4342 步收敛 |
| 18.8453 | 19 | 0.9919 m | 错位 | ✘ ratio 恒为 1.0 |
| 19.0000 | 18 | 1.0556 m | 错位 | ✘ ratio 恒为 1.0 |

> 注意第 3 行：**把段数减一同样破坏共形性**。这说明该失效模式不能通过"微调段数"规避，必须从根本上保证单元尺寸一致。

**对策**：将条带右边界**吸附到整数**（`xr = round(xr)`），令 `nx == xr`，从而保证单元尺寸恰为 1.000 m、与下部块共形连通。代价是阶梯在 x 向被量化为 1 m，属可接受的几何近似。

**修复效果**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 自平衡 | ratio 恒 1.0，200 000 步不收敛 | **4238 步收敛，8 s** |
| 特征步数（SSR 标定） | 43 551 | **5149** |
| SSR 结果 | 任何区间均 `Not Valid` | **FOS = 1.32** |

**特征步数由 43 551 降至 5149** 是网格连通性恢复的独立佐证——该量由自平衡态的刚度状态标定，两块不连通时其值被严重高估。

**方法论警示**：该失效同时具备 **C3（静默失败）** 与 **C5（几何/拓扑）** 双重属性，且具有极强的欺骗性：

- 无报错（`***` = 0）
- 有产物（`.sav` 正常写出）
- 有"合理"的数值（`ratio` = 1.0 是一个合法取值）
- **唯一异常信号是"数值完全不动"**

若仅以"是否报错""是否产出文件"作为判据，该失效将完全逃过检测。**唯一可靠的检出方式是检查物理量是否随计算推进而变化**——本案例中即 `ratio-local` 必须单调下降。这一检查应当被纳入任何数值流程的强制校验项。


### 5.4 ★ 关键发现：不存在统一的"收敛判据"

**这是本文最具方法论价值的数值发现。**

在参数化批量计算中，低强度算例的自平衡阶段出现**无限挂起**：无报错、无超时、无产物。逐层排查后确认这**不是软件缺陷，也不是脚本错误**，而是**物理与判据的错配**。

对同一算例（c=10 kPa, φ=15°，即 Bishop 判定的 FOS ≈ 0.70，本质上不稳定）施加三种自平衡判据：

**表 12 自平衡判据对照实验**

| 判据 | 耗时 | 终止步号 | 终止时不平衡力比 | 错误计数 | 产出 .sav |
|---|---|---|---|---|---|
| `ratio-local 1e-5` | 421 s | 135 738 | **0.990** | 0 | ✗ |
| `ratio-average 1e-4` | 902 s | 280 186 | 1.84 × 10⁻³ | 0 | ✗ |
| `cycles 3000`（硬截断） | **9 s** | 3 000 | — | 0 | ✔ |

三种判据下的**错误计数均为 0**。

**机理**：`ratio-local` 是**局部**不平衡力比。稳定边坡在重力作用下，不平衡力单调衰减，该比值从 1.0 降至 10⁻⁵ 量级（基准算例 4342 步即达标）。但不稳定边坡在重力下**持续塑性流动**，滑体不断产生新的不平衡力，该比值在 0.3–0.7 之间**永久震荡**——"力平衡"这个目标对该系统**在物理上不存在**。

**方法论结论**：

> **不存在适用于所有工况的统一收敛判据。**
> 自平衡（求力平衡）与强度折减（求强度储备）是**两个不同的数学问题**。
> 对"注定要被折减至破坏"的算例施加严格力平衡判据，是把两个问题错误地合并处理。

**本文的解决方案**：采用**双判据取先到者**：

```
model solve ratio-local 1e-5 cycles 20000
```

- **稳定算例**：在数千步内满足 1e-5，提前退出，行为与单一判据完全一致（实测基准算例仍在 4342 步收敛，耗时 13 s）；
- **不稳定算例**：由 20000 步上限兜底截断，取得"变形已充分发展"的初始状态，后续 SSR 折减照常进行（实测耗时降至 69–72 s，且 `.sav` 正常生成）。

**修复效果的量化对比**：

| 环节 | 修复前 | 修复后 |
|---|---|---|
| 低强度算例自平衡 | 无限挂起（> 1200 s 被杀） | 69–72 s 正常完成 |
| `.sav` 产出 | 缺失（导致下游全链失败） | 正常生成 |
| 参数化批次完整性 | 10/16 算例失败 | 全部可算 |

**该发现的可推广性**：任何"先求平衡、再施加扰动/折减"的两阶段数值流程，都面临同一风险。判定标准应当是：**若目标状态本身不满足平衡条件，则不得对第一阶段施加平衡判据**。这一原则与具体软件无关，适用于非线性有限元、离散元等所有同类流程。

### 5.5 位移与塑性区（基准算例）

**表 13 位移计算结果**

| 状态 | 最大总位移 \|u\| | 最大竖向位移 u_y | 最大水平位移 u_x |
|---|---|---|---|
| 自重平衡态 | 35.1 mm | −35.1 mm | 9.5 mm |
| 临界态（FOS-Stable） | 129.6 mm | −99.4 mm | 118.3 mm |
| 失稳态（FOS-Unstable） | **404.6 mm** | −329.4 mm | 390.9 mm |

三态位移呈清晰层级：自重 35.1 mm → 临界 129.6 mm → 失稳 404.6 mm（约 11.5 倍于自重态）。

自重态以竖向沉降为主（35.1 mm），符合重力加载特征。临界态与失稳态下**水平位移反超竖向位移**，表明滑体运动转为以水平向坡外滑移为主导，是边坡失稳的典型运动学特征。

**表 14 塑性区统计（单元数）**

| 状态 | 弹性 | 剪切破坏（当前） | 拉伸破坏（当前） | 曾屈服 |
|---|---|---|---|---|
| 自重平衡态 | 1308 | 430 | 0 | 932 |
| 失稳态 | 0 | 819 | 57 | 1794 |

> **量测语义说明（易错点）**：FLAC3D 的 `zone.state` 返回**整数位掩码**，其中 `shear-n`（值 1）表示**当前**处于剪切屈服状态，`shear-p`（值 4）表示**历史上曾经**剪切屈服（`p` = past）。二者不可混同：只有 `shear-n` 才代表当前的活动塑性区。
>
> 此外需注意，`fos-Unstable.sav` 存档对应**完全失稳状态**（2670/2670 个单元全部进入 `shear-n` + `tension-n`），而非某个中间滑面形态。若将其误读为"滑裂面"，会得出错误的机制结论。正确的滑裂面判读应基于 `fos-Stable.sav`（临界态）。

**应力场**：竖向应力 σ_yy 随埋深单调增大，底部最大压应力约 −430 kPa；剪应力 σ_xy 在坡脚及潜在滑裂面附近显著集中（峰值约 +43 kPa），其空间位置与塑性贯通带吻合。

**破坏机制**：综合位移场、塑性区与应力场，基准边坡表现为**典型的圆弧形旋转滑动破坏**——潜在滑裂面自坡趾 (≈19, 10) 沿弧线向上延伸，于坡顶内缘 (≈10, 18) 附近剪出；滑体位移自滑裂面向坡面递增，坡面中部位移最大，呈"头部拉伸—中部推移—趾部剪出"的完整运动图景。

**关键结论**：改用 `-b` 批处理模式后，**交互通道开销从 95 % 降至可忽略**。早期基于控制台屏幕抓取的方案需在每条命令后轮询 4 s 并重启进程（约 8 s/次），交互开销远超计算耗时；改为批处理流式输出后，全流程为纯计算耗时。

进一步优化空间：

1. **自适应 bracket 区间**——按算例强度预判 FOS 量级，避免区间未覆盖导致的二次求解（本文 `c10p15` 即因 FOS 低于 0.8 而需放宽下限重算）；
2. **网格共形性前置校验**——建模后即检查各子块单元尺寸是否一致，可在数秒内排除 §5.3.1 那类需 242 s 才能暴露的静默失效；
2. **多算例并行**——参数化批次中各算例相互独立，可并行调度；
3. **减小 SSR 二分区间**——由 [0.3, 3.0] 收窄至预判 FOS 附近，可显著降低迭代轮数。

## 6 能力边界与安全实践

### 6.1 三层次能力边界框架

基于本次实证，本文提出 AI 在岩土数值模拟中的三层次能力边界框架（表 12）。

**表 12 AI 能力边界三层次框架**

| 层次 | 环节 | 判断依据 |
|---|---|---|
| ✅ **可托付** | 几何建模、网格生成、材料参数批量赋值、边界条件施加、求解流程编排、数据提取、结果可视化、错误诊断与修正 | 规则明确、可完全形式化、结果可自动校验 |
| ⚠️ **需人类把关** | 物理假设的合理性、本构模型选择、材料参数取值依据、结果的工程解读、边界条件与实际工况的匹配度 | 需专业判断、涉及经验与规范、影响结果的物理正确性 |
| ❌ **不可托付** | 无实测数据支撑的参数确定、涉及重大工程安全的最终判据 | 关涉工程安全责任，责任主体必须是人 |

### 6.2 需人类把关环节的具体说明

以本次实验为例，说明"需人类把关"的具体含义：

**(1) 物理假设的合理性**：本文假设坡趾位于 y = 10 m。该假设的**合理性判断需要人类的工程经验**——AI 可以指出该假设的两种可能（y = 10 或 y = 0）并分析差异，但无法判断哪一项符合委托方的实际意图。

**(2) 材料参数取值依据**：本文采用的 c = 30 kPa、φ = 25° 为**通用假定值**，未依据勘察数据。在工程实践中，参数取值直接影响 FOS 结果，必须由具备依据的工程师确定。

**(3) 本构模型选择**：本文采用 Mohr-Coulomb 模型。但对于实际边坡，是否需考虑应变软化、剪胀性、非饱和特性等，**需要基于岩土类型与工程条件判断**，属专业决策。

**(4) 结果的工程解读**：FOS = 1.685 是否满足要求，取决于工程等级、规范要求、后果严重性。**同一数值在不同工程背景下的可接受性不同**，这需要专业判断。

### 6.3 本文的正面案例：AI 主动升级不确定性

本次实验中，AI Agent 在完成建模后，**主动识别到自身对几何的理解存在不确定性**（坡趾标高有两种可能解释），并以图形方式向委托方提请确认，而非擅自继续。

**该行为应成为 AI 参与工程计算的标准行为规范。** 其价值在于：

- 它把 C6 类（认知错误）的风险**从"事后发现"前移至"事前拦截"**
- 它明确了 AI 与人类的责任界面：**AI 负责识别不确定性，人类负责消解不确定性**

值得记录的是，本次委托方**未对该确认请求作出明确答复**。AI Agent 在此情况下选择**显式记录假设并继续执行**，同时在结果中标注该假设为前置条件。这一处理方式在"推进任务"与"标注风险"之间取得了平衡，但更佳实践是：**对影响结果有效性的关键假设，应坚持等待明确确认。**

### 6.4 人机协作流程建议

基于上述分析，本文建议的岩土数值模拟人机协作流程如下：

1. **人类**：明确物理问题、提供参数依据、设定本构与判据、确认关键假设
2. **AI**：完成建模、网格、求解编排、数据提取、可视化、错误诊断
3. **AI**：对不确定内容**主动暂停并升级**，不擅自决策
4. **人类**：审核 AI 输出的物理合理性，通过验证锚点独立复核
5. **人类**：承担最终工程判断与责任

**核心原则**：**AI 是流程执行者与纠错助手，而非工程判断的责任主体。**

## 7 结论与展望

### 7.1 结论

(1) **AI Agent 可自主完成岩土数值模拟的全流程。** 本实验中，AI Agent 在 96 分钟内独立完成三维边坡的建模、自重平衡、强度折减法安全系数计算（FOS = 1.685）及结果可视化，全过程 2670 单元规模，无需人工干预即可完成流程性工作。

(2) **AI 的脆弱性集中于"不可见的错误"。** 本文提出科学计算中 AI 错误的六分类学，其中 C3 静默失败（不报错但语义失效）具有最高风险：它绕过 AI 依赖的"报错-修正"闭环，且污染中间结果并向下游传播。应对策略是**主动构建输出一致性校验**，而非被动等待报错。

(3) **AI 无法仅凭文档推理正确使用复杂专业软件。** C2 隐性约束（本文中 SSR 应变模式要求的两项互斥报错）表明，专业软件的配置知识大量存在于文档之外，AI 必须依赖**实测反馈闭环**。

(4) **AI 的可靠性提升应聚焦于两个关键界面。** 错误风险矩阵显示，投入重点应为 C3（建立检测机制）与 C6（建立升级机制），而非均匀分配于所有错误类别。

(5) **科学计算中的 AI 应用必须提供不可伪造的验证锚点。** 本文建立的三层验证体系（软件原生二进制存档、求解器自写日志、物理一致性检验）可作为通用范式。

### 7.2 研究局限

(1) **单一案例**：本研究仅涉及一个边坡案例与一款软件（FLAC3D）。结论的普适性有待多案例、多平台验证。

(2) **缺乏对照实验**：未设置"人工操作"对照组，无法定量比较效率与出错率。

(3) **参数未依据勘察数据**：材料参数为通用假定值，本文的 FOS 结果不具备特定工程的直接参考价值。

(4) **交互通道非最优**：受限于官方 MCP 通道不可用，本文采用的控制台直驱方案引入了显著的效率损失，其结论（尤其是耗时分析）不代表最优通道下的表现。

(5) **关键假设未获确认**：坡趾标高假设未获委托方明确确认，构成本文结果的前置条件。

### 7.3 展望

(1) **官方进程内通道的普及**：随着 MCP 等标准化协议在专业软件中的落地（如 Itasca 系列），AI 与求解器的交互效率与可靠性将显著提升，本文的"瓶颈分析"将被重新评估。

(2) **AI 科学计算的验证标准与审计规范**：需要建立行业标准，规定 AI 参与的计算必须提供何种级别的验证证据、如何记录决策链、如何界定责任。

(3) **多案例、多平台的横向研究**：在更广泛的软件生态（ABAQUS、PLAXIS、GeoStudio 等）与更复杂的工程场景（多地层、地下水、动力荷载）中检验本文框架的适用性。

(4) **AI 自我不确定性量化的能力建设**：C6 类错误的根本解法，是让 AI 具备"知道自己不知道什么"的能力。本文的正面案例（主动升级几何假设）表明这一能力已有雏形，但需系统性强化。
